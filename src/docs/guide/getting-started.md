# 快速入门指南

本文档将帮助你快速上手 MkNexus，涵盖安装、配置和日常使用。

## 环境要求

| 依赖 | 最低版本 |
|------|----------|
| Node.js | 18+ |
| npm / yarn / pnpm | 任意 |
| 浏览器 | Chrome 90+ / Firefox 88+ / Safari 14+ / Edge 90+ |

## 安装步骤

### 1. 进入项目目录

```bash
cd /mnt/agents/output/app
```

### 2. 安装依赖

```bash
npm install
```

依赖已包含在 `package.json` 中，无需额外安装。

### 3. 添加你的文档

将 Markdown 文件放入 `src/docs/` 目录。支持子目录嵌套，文件名和目录名都可以使用中文。

```bash
# 创建文档目录结构
mkdir -p src/docs/项目文档
mkdir -p src/docs/技术文档

# 添加文档
cat > src/docs/项目文档/需求分析.md << 'EOF'
# 需求分析

## 项目背景

本文档描述项目的整体需求...
EOF

cat > src/docs/技术文档/架构设计.md << 'EOF'
# 架构设计

## 系统架构图

```
前端层    →   API 网关    →   服务层    →   数据层
 React        Nginx         Node.js       PostgreSQL
```
EOF
```

### 4. 启动服务

#### 方式 A：开发模式（即时热更新）

```bash
npm run dev
```

打开浏览器访问 `http://localhost:3000`。

**特点：**
- 修改已有文档 &rarr; 浏览器**即时刷新**
- 新增文档后 &rarr; **手动刷新**页面可见
- 最适合日常写作

#### 方式 B：自动构建模式（推荐对外服务）

```bash
npm run docs:start
```

打开浏览器访问 `http://localhost:8080`。

**特点：**
- 新增/修改/删除文档 &rarr; **自动构建 + 浏览器刷新**
- 无需手动干预，适合团队协作
- 完整链路见下文

#### 方式 C：自定义端口

```bash
# 服务器使用 3000 端口
npm run docs:serve -- 3000

# 监听脚本也对应修改
npm run docs:watch -- 3000
```

## 自动构建模式详解

`npm run docs:start` 同时启动两个进程：

### 进程 1：静态文件服务器（`serve.cjs`）

- 提供 `dist/` 目录的静态文件访问
- 注入 WebSocket 客户端代码到首页
- 提供 `/__notify` HTTP API 用于接收构建通知
- WebSocket 服务器挂载在 `/__ws` 路径

### 进程 2：文件监听与构建（`watch-and-build.cjs`）

- 使用 `chokidar` 监听 `src/docs/` 目录
- 支持的事件：文件新增、修改、删除
- 防抖处理：500ms 内多次变化合并为一次构建
- 构建队列：如果构建过程中又有新变化，排队等待
- 构建完成后通过 HTTP 通知服务器

### 工作链路

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  编辑文档    │────▶│ chokidar 监听 │────▶│ npm run build │
│  保存文件    │     │ (防抖 500ms) │     │  (约 12 秒) │
└─────────────┘     └──────────────┘     └──────┬──────┘
                                                 │
                          ┌──────────────────────┘
                          ▼
                   ┌─────────────┐
                   │  POST /notify │
                   │  {reload}    │
                   └──────┬──────┘
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
        [浏览器A]    [浏览器B]    [浏览器C]
        WebSocket   WebSocket   WebSocket
        自动刷新     自动刷新     自动刷新
```

### 命令速查

| 命令 | 作用 | 端口 |
|------|------|------|
| `npm run dev` | Vite 开发服务器 | 3000 |
| `npm run docs:serve` | 生产静态服务器 | 8080 |
| `npm run docs:serve -- 3000` | 自定义端口 | 3000 |
| `npm run docs:watch` | 文件监听 + 自动构建 | - |
| `npm run docs:start` | 同时启动 serve + watch | 8080 |
| `npm run build` | 手动构建一次 | - |

## 文档组织规范

### 目录结构

```
src/docs/
├── intro.md                    # 首页文档（建议保留）
├── 01-快速入门/
│   ├── 01-安装配置.md
│   └── 02-基本用法.md
├── 02-进阶功能/
│   ├── 01-自定义样式.md
│   └── 02-部署指南.md
└── 03-参考资料/
    ├── api参考.md
    └── 常见问题.md
```

### 命名规范

| 规范 | 说明 | 示例 |
|------|------|------|
| 文件扩展名 | 必须为 `.md` | `intro.md` |
| 排序前缀 | 数字前缀控制排序 | `01-安装.md` |
| 命名风格 | 短横线连接的小写/中文 | `getting-started.md` |
| 子目录 | 支持任意层级嵌套 | `guide/start.md` |

前缀中的数字和分隔符在导航中会被自动去除，仅用于控制排序顺序。

### 最佳实践

1. **每个目录放一个 `README.md` 作为索引页**
2. **文件名反映内容主题**，避免 `doc1.md`、`doc2.md` 这类无意义名称
3. **控制单个文档长度**，建议不超过 5000 字，过长则拆分为子文档
4. **在文档开头添加一级标题**，作为文档标题显示在导航中
